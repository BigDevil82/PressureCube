# 增压舱钢结构优化系统 — WebCAD HTTP 三维建模对接任务说明

## 1. 项目背景与开发目标

本项目是与中建三局合作的**模块化增压氧舱／增压建筑钢结构智能优化设计**项目。现有 Python 工程已经实现：

1. 增压舱钢结构的参数化建模；
2. 有限元分析及相应约束检查；
3. 自动截面优化，输出最终的杆件布置和截面尺寸。

当前优化程序中的杆件主要以**线单元（轴线、两端节点、截面属性）**表示。下一步需要对接中建三局的 **WebCAD BIM 平台**，将**最终优化结果**通过 HTTP 接口创建为具有真实截面的**三维钢结构实体构件**，并保存到 WebCAD 当前模型中。

**本次只开发“优化结果 → WebCAD 实体模型”的数据转换与接口调用层。** 不重写优化算法、有限元计算、已有参数化建模逻辑；不自行构造网格或从零开发实体建模内核。优先使用 WebCAD 内置的 `structure.*` 钢梁、钢柱构件。

## 2. 实际结构范围（已确认）

结构仅包含以下 **4 类构件**：

| 内部构件组 | 几何与含义 | WebCAD 业务构件 | 截面约束 |
|---|---|---|---|
| 框架柱 | 四个角部的竖向框架柱 | 钢柱 `*SteelPillar` | 该组使用同一截面 |
| 主梁 | 主承重梁 | 钢梁 `*SteelGirder` | 该组所有杆件使用同一截面 |
| 次梁 | 次承重梁 | 钢梁 `*SteelGirder` | 该组所有杆件使用同一截面 |
| 支撑梁 | 结构体系中的支撑梁，**不是斜撑** | 普通钢梁 `*SteelGirder` | 该组所有杆件使用同一截面 |

- **没有斜梁、斜撑**，本阶段不需要使用 `structure.horizontalSupport` / `structure.verticalSupport` 等专用支撑类型。
- 结构截面仅有 **3 种类型**：**方钢管、工字钢、槽钢**。其中方钢管是**空心薄壁方钢管**，不是实心方钢。
- 四类构件对应四组优化截面参数，**每组内部统一使用一个最终截面**；不同组可以采用相同或不同截面类型／尺寸，实际由优化结果决定。
- 不需要创建节点连接板、螺栓、焊缝、加劲肋、舱壁、建筑构件或机电构件。后续如有需要再单独扩展。

## 3. 推荐的数据流

```text
现有优化程序
  └─ 最终优化结果（构件组 + 杆件节点坐标 + 截面类型/尺寸）
       └─ WebCAD 导出适配层（本次新增）
            ├─ 从仓库现有数据结构提取构件列表
            ├─ 单位、坐标与截面朝向检查/转换
            ├─ 构件组 × 截面类型 → WebCAD type/业务编码
            ├─ 截面尺寸 → sectionParams
            ├─ HTTP 鉴权、获取 sessionId
            ├─ 逐根调用 cad.node.create；记录 nodeId 与结果
            └─ 核对、cad.document.save
                    └─ WebCAD 当前编辑模型中的三维实体钢结构
```

**请先阅读现有仓库**，找到最终杆件坐标、分组、优化截面参数的真实数据来源，复用现有实体与配置。不要凭空设计另一套优化结果格式并要求项目迁移。

建议对外提供一个清晰入口，例如 `export_to_webcad(optimization_result, config)`（名称按仓库风格决定），让优化结束后可以直接触发导出。WebCAD 对接模块与优化求解模块应解耦。

## 4. HTTP 建模接口与调用顺序

《WebCAD MCP 建模指南》第 1–4 页说明：MCP 和 HTTP 调用的是**同一套工具**。本次仅使用 **HTTP 方式**，**不接入 MCP 客户端**。

### 4.1 前置条件

- 用户先在浏览器中**登录 WebCAD 并打开目标模型编辑页面**，且保持页面不关闭。
- 模型实际由浏览器中的 WebCAD 编辑器执行建模；HTTP 不是无需浏览器的纯后台离线建模接口。
- 同一账号建议只打开一个编辑页面；如有多个页面，必须使用正确 `sessionId`。
- 获取 `access_token` 的**准确登录地址、授权流程、请求参数及权限**，请查看另行提供的《mcp服务接入说明》；不要自行猜测。

### 4.2 HTTP 接口

| 目的 | 方法和路径 | 备注 |
|---|---|---|
| 查询编辑会话 | `GET /api/cad-agent/sessions` | 从返回中选择目标页面的 `sessionId` |
| 执行任意建模工具 | `POST /api/cad-agent/sessions/{sessionId}/calls` | 所有工具统一经此入口调用 |

请求须携带相应 `Authorization` token（具体格式依接入说明）。调用 `POST .../calls` 的通用请求体：

```json
{
  "tool": "cad.node.create",
  "args": {
    "type": "structure.squareTubeSteelGirder",
    "params": {}
  }
}
```

上面 `params` 为空只是**统一封装格式示例**，不是可执行建模请求；完整创建示例见第 6 节。

### 4.3 实际会用到的工具

| 工具 | 用途 | 使用阶段 |
|---|---|---|
| `cad.node.list_types` | 查看支持的构件类型 | 初次开发／联调 |
| `cad.node.describe_type` | 获取具体类型的 `createSchema`、`updateSchema` | **必须**：初始化确认六种构件类型的字段 |
| `cad.node.create` | 逐根创建三维构件 | **必须**：核心批量建模 |
| `cad.node.get_by_id` | 根据返回的 `nodeId` 核查结果 | 建议：先样例、后抽检 |
| `cad.document.save` | 保存整个模型 | **必须**：建模完成后调用 |
| `cad.node.delete` | 删除先前生成的构件 | 建议：便于重新导出／清理 |
| `cad.node.update` | 修改已存在构件的部分属性 | 可选：第一版无需支持 |

推荐执行顺序：

1. 检查平台连接、认证和目标编辑页面，取得 `sessionId`；
2. 调用 `describe_type` 核对所需类型及参数；
3. 先创建 **1 根柱 + 3 种截面的代表性梁（按实际存在的类型选择）**，人工检查位置、截面朝向、尺寸；
4. 正式导出时逐根 `cad.node.create`，逐条检查响应并记录 `nodeId`；
5. 所有构件确认无误后调用 `cad.document.save`。

**平台文档明确：一次 `cad.node.create` 只创建一个构件**，批量建模需循环调用。失败时检查响应中的 `ok: false` 与 `error.code` / `error.message`。不要根据 HTTP 状态码 单独判断业务成功。

## 5. 构件 type、业务编码与截面参数映射

参照《WebCAD MCP 建模指南》第 12–14 页“结构构件”章节。**柱和梁的截面字段一致，但 type 和业务编码不同。**

### 5.1 构件类型与业务编码

| 截面类型 | 钢梁 type | 钢梁 `componentCode` | 钢柱 type | 钢柱 `componentCode` |
|---|---|---|---|---|
| 空心方钢管 | `structure.squareTubeSteelGirder` | `15-001-0001` | `structure.squareTubeSteelPillar` | `02-003-0001` |
| 工字钢 | `structure.gongShapedSteelGirder` | `15-001-0003` | `structure.gongShapedSteelPillar` | `02-003-0003` |
| 槽钢 | `structure.channelSteelGirder` | `15-001-0002` | `structure.channelSteelPillar` | `02-003-0002` |

- 所有普通钢梁 `typeCode = "15-001"`；所有钢柱 `typeCode = "02-003"`。
- **工字钢**使用 `gongShapedSteel*`，**不是** `hShapedSteel*`（后者是 H 型钢，平台分为两个类别）。
- 三组梁（主梁、次梁、支撑梁）按**相同的梁类类型映射规则**生成，差异体现在杆件位置、截面值和业务名称，不应硬编码成三种固定截面类型。
- 对每个构件，可保存 `id` / `name` 等属性以便按组查找，但应遵守该类型的有效 Schema。

### 5.2 `sectionParams` 字段

| 截面类型 | `sectionParams` 的尺寸字段（单位 mm） | 含义 |
|---|---|---|
| 方钢管 | `sideLengthA`、`sideLengthB`、`wallThicknessT`、`outerArcRadiusR` | 两侧边长、壁厚、外圆角半径 |
| 工字钢 | `height`、`legWidthB`、`thicknessD`、`thicknessT`、`radiusR`、`legArcRadiusR1` | 截面高、腿宽、腹板厚、平均腿厚、内圆角半径、腿端圆弧半径 |
| 槽钢 | 与工字钢相同 | 同上一行 |

- 创建时所有钢梁、钢柱截面尺寸均写在 `params.sectionParams` **对象内部**，不可散放在 `params` 顶层。
- 如果优化模型只提供高度、宽度、厚度，而没有给出圆角相关参数：应先查询 `describe_type` 中的默认值与必填约束，并按**实际型钢型号／项目约定**决定如何补齐；不要臆造圆角规格。
- 官方文档指出截面尺寸必须大于 0；还应增加工程合理性校验，如方钢管壁厚不能使内孔尺寸非正。
- 优化模型中的截面定义若与 WebCAD 的国标型钢尺寸定义不完全相同，必须在适配层明确换算或向技术人员确认，不能只根据字段名称硬套。

## 6. 单根构件完整 HTTP 请求示例

示例：沿 X 轴布置的一根空心方钢管**钢梁**（下面尺寸仅用于测试，**不是当前项目真实优化结果**）。

`POST /api/cad-agent/sessions/{sessionId}/calls`

```json
{
  "tool": "cad.node.create",
  "args": {
    "type": "structure.squareTubeSteelGirder",
    "params": {
      "id": "webcad_main_beam_001",
      "name": "主梁-001",
      "startPoint": {"x": 0, "y": 0, "z": 3000},
      "endPoint": {"x": 4000, "y": 0, "z": 3000},
      "sectionParams": {
        "sideLengthA": 100,
        "sideLengthB": 100,
        "wallThicknessT": 5,
        "outerArcRadiusR": 8
      },
      "baseType": 0,
      "crosssectionRotationAngle": 0,
      "typeCode": "15-001",
      "componentCode": "15-001-0001"
    }
  }
}
```

> 示例中的 `id`、`name` 和旋转参数，仍应通过相应 `createSchema` 核对有效性；如实际类型 Schema 不接受某可选字段，应按 Schema 删除该字段。`0°` 为演示值，不表示所有工程杆件都可以固定取 0°。

成功响应在指南中的格式类似：

```json
{
  "ok": true,
  "value": {
    "nodeId": "...",
    "type": "...",
    "semanticKey": "...",
    "properties": {}
  }
}
```

记录返回 `value.nodeId` 与原杆件 ID 的映射，用于核对、删除、重新导出。**所有构件创建成功后**，再通过相同 POST 入口执行保存：

```json
{
  "tool": "cad.document.save",
  "args": {}
}
```

## 7. 坐标、截面朝向及结构准确性

这是除了鉴权以外最重要的工程对接检查项。

1. **单位**：WebCAD 长度单位一律为 **mm**，角度单位是**度**；现有优化／FEA 模型如以 m 为单位，则在导出边界统一乘以 1000（不可重复换算）。
2. **世界坐标系**：WebCAD 采用世界坐标，**Z 轴向上**。检查本地模型原点、XYZ 方向和正负方向是否一致，需要时进行统一坐标变换。
3. **杆件轴线**：梁 `startPoint` / `endPoint` 表示轴线起终点；柱对应柱底与柱顶中心。竖向柱宜从下向上定义，且起终点不能重合。
4. **截面定位**：`baseType` 表示截面相对于杆件轴线的定位点，**`0` 为中心**。若当前杆单元轴线穿过截面形心，可先用 `0` 试建并确认；不要在未验证前套用其他定位。
5. **截面旋转**：`crosssectionRotationAngle` 是截面绕杆件轴线的旋转角（度），**工字钢和槽钢尤其重要**。应检查现有有限元模型的局部轴定义，并建立与 WebCAD 的方向换算。没有充分依据时，不要强制将所有构件设为 0°。
6. **工作面与材质**：首版优先利用世界坐标定位；若平台当前工作面影响部分构件的朝向／定位，则按官方 Schema 显式指定工作面或方向。`materialId` 仅能引用 WebCAD 模型中已存在的材质 ID，不要随意生成。
7. **实体与有限元的一致性**：验收时核对四角柱数量与位置、各类梁的空间布置、每个构件的截面族／尺寸和截面朝向，确保导出的是**实体截面**而不仅是轴线。

## 8. 建议的代码改造范围

**先检查现有仓库**，沿用项目已有的 Python 版本、数据结构、依赖管理、日志和配置风格；模块、函数名可按实际组织，不必拘泥以下命名。

建议包括：

- `WebCADClient`：认证信息注入（按登录文档）、session 查询、通用 `call_tool()`、请求超时与异常处理；不在源码中写死 token / 密码。
- `WebCADSectionMapper`：根据“钢梁/钢柱 + 方钢管/工字钢/槽钢”映射 `type`、业务编码和 `sectionParams`；做字段校验。
- `WebCADExporter`：读取现有优化结果，构建逐根杆件请求，执行导出、记录 nodeId 和创建结果，保存模型。
- 统一配置：服务器基础地址、身份验证、目标 session（自动发现或显式指定）、单位缩放、可选模型导出设置；敏感信息通过环境变量或既有项目配置管理。
- 增加**预览／dry-run 模式**：只生成和校验构件 JSON 列表，不连接／修改 WebCAD；方便在没有账号权限时做本地测试。
- 保存导出记录：原始构件 ID、组别、截面类型、WebCAD type、`nodeId`、状态和错误信息，支持定位失败杆件。

**重复导出策略**：避免每次点击导出都把构件追加到同一模型。首版可采用“保存本次生成的 nodeId → 下次导出前提示／显式清理旧构件 → 重新创建”的方式；不要误删用户自己在 WebCAD 中创建的其他构件。实现删除前应明确区分本项目生成构件与原有构件。

**失败处理**：每次调用检查 `ok`，失败时给出可定位的构件信息；因网络超时而结果不确定时，应先查询或核对再重试，避免因重复提交而创建两根相同构件。批量建模初期优先串行、限速和明确日志，不假定平台支持并发批量事务。

**后续可选功能**：`cad.node.update` 支持修改部分参数，但文档指出钢梁／钢柱截面更新时尺寸直接放在 `patch` 中（**不包** `sectionParams`），起终点通常需要删除重建。首版可以不做在线更新，只做好安全重建。

## 9. 实施顺序与验收标准

### 建议实施顺序

1. 阅读本文件、两份正式接口文档和现有仓库；明确真实数据入口、长度单位和局部坐标约定。
2. 打通登录／获取 token／获取正确 sessionId／`describe_type`。
3. 实现截面 mapper 与 dry-run；准备四类构件的测试数据、覆盖三种截面。
4. 先在 WebCAD 中创建少量测试柱、梁，人工确认三维实体、坐标与朝向。
5. 连接完整优化输出，批量导出全部四类构件；记录每根的请求、结果与 nodeId。
6. 核查完整模型后保存，测试错误恢复和重复导出／清理机制。

### 第一版验收标准

- [ ] 能直接读取现有优化程序的最终结果，无须重复手工录入构件参数。
- [ ] 框架柱、主梁、次梁、支撑梁四组均能正确导出；每组截面一致。
- [ ] 三种截面（空心方钢管、工字钢、槽钢）都能生成有真实截面的 WebCAD 三维实体。
- [ ] 杆件数量、起终点、单位、空间布局、截面尺寸和朝向与本地优化模型一致。
- [ ] 能自动或按配置指定 `sessionId`；对未登录、页面未打开、token 无效等情况有清晰报错。
- [ ] 每根杆件成功／失败可追踪；出现部分失败时不误报整体成功。
- [ ] 能调用 `cad.document.save`，刷新 WebCAD 页面后模型仍保留。
- [ ] dry-run 可独立执行；重复导出不会无提示地叠加重复构件。

## 10. 需由正式文档／联调最终确认的项目

请 Codex **不要猜测**下列事项：

- 登录接口地址、HTTP 鉴权方式及 token 续期策略：来自《mcp服务接入说明》。
- `GET /sessions` 的具体响应结构及目标页面识别方式：以实际返回为准。
- 预置类型的必填项、默认值、是否接受 `id/name`、材料／工作面属性及圆角参数：以 `cad.node.describe_type` 实时 Schema 为准。
- 本地现有截面优化参数与平台 `sectionParams` 的尺寸定义是否一一对应：根据仓库数据与型钢规格判断，必要时向中建三局确认。
- 有限元局部坐标、截面朝向与 WebCAD 旋转角之间的对应关系：通过 1 根样例实测确认。
- 是否需要把四类构件的工程分类写入 `name`、`userData`、`businessProperties` 等字段：按现有仓库和有效 Schema 决定，不影响第一版实体创建的首要目标。
